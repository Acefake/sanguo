# 出阵与主帅后台决策

2026-10-04。

## 决策时机

真实模型接入后台调度器，日期推进不等待 HTTP 请求。模型只为军团主帅提出候选军令；部将执行规则任务。等待期间沿用已有任务，由本地规则处理必要的部署和紧急行动。

- 首次部署请求一次。
- 新发现敌军或粮道、职务任务变化、部队结束/撤退、士气低于30、组织低于25、粮食少于3日、连续受阻至少2日、夹击或至少3支相邻敌军、补给中断及玩家军令变化，触发态势复核。
- 状态变化至少相隔2个游戏日；稳定局势每5日复核。普通移动与每次伤亡不重复请求。
- 同一请求未完成时不重复提交。回复在随后游戏日边界核对指挥权、部队状态、危机阈值及玩家军令，再由现行规则执行；超过10游戏日的回复舍弃。重开场景使旧回复失效。
- 新敌情不会自动使全部候选回复失效，但执行仍需通过当前合法性检查。

调度测试：延迟350ms的模拟模型，单日约29ms完成。真实 Ollama Qwen3:1.7b，两名主帅一批约5687ms、合法回复2/2；三日模拟日结42/42/26ms，零碰撞，后两日4/6支部队接战。推理已关闭，模型本身的耗时仍受GPU负载和上下文影响；这些数据不代表3D整帧性能。

## 全局格子

小沛战斗、分队目标、包围判定与3D位置使用 `rtk14_hex_grid.gd` 原有220×220共48400个全局格子的整数ID、六邻接、坐标转换与不可通行地形；不叠加另一套局部网格。小沛测试仍限制在既定交战区域，普通战略行军仍沿城市路网；未宣称全国自由格行军已完成。

`global_battle_grid_validation.gd` 检查真实全局ID、世界位置拾取往返、六邻接距离、地形一致性和连续8日移动。

## 出阵界面

入口仍为地图出征/目标选择，改成纸面中央界面：出发城、目标、主帅、主帅/副帅/军师肖像、随军人员、兵力滑条、五轴军事雷达、真实编组预览、携粮/留守/通路日数、决定与返回。

雷达显示主帅真实带兵、布阵、治军、奇袭、智计，刻度120。随军职务由人物位置适性生成，预览与实际职务、分队数量通过测试核对。兵力受现有城池留守、主帅容量与粮食规则限制，按现有步弓骑库存综合动员。未加入尚无规则实现的兵器、舰船或虚构战法。

纸面、栏标题、雷达底图来自用户指定 SAN8R PNG 目录，逐张打开核对并裁切；`assets/war/dispatch/sources.json` 记录原路径、裁切框、源文件和输出SHA256。按钮沿用项目现有UI皮肤并调整颜色。

实机截图：`army-assets/dispatch-view.png`。验证覆盖纯预览不扣资源、选定兵力真正动员、雷达五项、编组职务一致性；并通过战争、军令、军团、战场、包围、小沛、全局格、模型协议和设置回归。
