# 人物战斗特色：实现与本地接入说明

分支 `feat/combat-officer-identity`，2026-10-21。对应方案 M1–M6（提交顺序 M1→M2→M6→M4→M5→M3）。

GitHub 上缺 15 个被 preload 的脚本（`scripts/agents/{officer_autonomy,officer_brain,tactical_evaluator,tactical_plan,unit_brain}.gd`、`scripts/war/{corps_structure,city_defense,duel_rules_v2,officer_role,battle_objectives,army_command_roles,duel_lines,report_policy,army_officer_visual,tactical_intent_overlay}.gd`）。本分支没有创建、猜写或删除对它们的引用。凡是需要这些脚本配合的地方，下面列出你在 Windows 本地要加的调用。

## 1. 模块一览

人物战斗相关的代码都在 `scripts/officers/`，数据在 `data/officers/`，测试在 `tests/officers/`。

| 文件 | 回答的问题 |
|---|---|
| `scripts/officers/trait_registry.gd` | 这支部队在当前情境下，某个 hook 被特性改了多少（已按上限夹住）；加载时校验数据 |
| `scripts/officers/officer_process.gd` | 属性 → 流程耗时/概率（能否做好）；GDD E(x)/u 曲线 |
| `scripts/officers/officer_conduct.gd` | 投入、追击、脱离、迎战、听参军、违令的阈值（倾向如何选择）；人格 + 局限特性 |
| `scripts/officers/signature_traits.gd` | 武圣、小霸王的执行 |
| `scripts/officers/career_templates.gd` | 生成将的 8 种职业模板 |
| `scripts/officers/officer_explain.gd` | 面板理由、军报署名、人物卡两面、模型上下文 |
| `data/officers/hooks.json` | hook 注册表、单来源与合计上限、条件字段 |
| `data/officers/traits.json` | 33 个特性定义 |
| `data/officers/officer_traits.json` | 18 名历史人物的 trait_ids 与卡面映射、推定条目 |
| `data/officers/process_profile.json` | 流程基准量（TaskProfile）与人格系数 |
| `data/officers/career_templates.json` | 职业模板 |

`scripts/war/officer_battle.gd` 已删除，调用方已迁移。部队与人物上的 `battle_traits` 字段改名为 `trait_ids`，旧档加载时自动擦除旧字段。

## 2. 属性各管一个流程（M2）

| 子属性 | 流程 | 进入结算的位置 |
|---|---|---|
| 带兵 | 命令整理耗时，容量 2+floor(6u) 个标准单元（2000 人），超出排队 | `issue_order` → 当天就绪度 |
| 布阵（新版“机动”） | 展开/整队、行军耗时 | `issue_order`、`march_speed` |
| 治军 | 轮换耗时 → 接战组织损失倍率；休整组织恢复 | `apply_loss`、`recovery` |
| 沉着 | 压力失误概率 | `pressure_error`（需 unit_brain 调用，见 §5） |
| 应变 | 重规划耗时 | `issue_order(plan_invalid=true)` |
| 料敌 | 敌情估计 σ、伏兵识破 | `estimate`、`ambush_read`（需 unit_brain 调用） |
| 奇袭 | 接触暴露概率 | `conceal_exposure`（需 tactical 调用） |
| 智计 | 计划遗漏；暂代攻坚准备（旧 25 键没有攻坚） | `plan_omission`、`engineering_rate`（围城已接） |
| 体魄 | 疲劳 | `fatigue_cost`、`recovery` |
| 威仪 | 主将光环强度与半径 | `aura_strength`、`aura_range` |
| 膂力/箭术/骑术 | 对应兵种的局部执行 ±6%（暂代兵种适性） | `power_breakdown.unit_skill` |
| 武艺 | 个人遭遇与单挑 | `personal_power`、`prowess` |

`combat_system` 的伤害主公式不变，只去掉了布阵/带兵/治军合成、将领防御和奇袭智计 tactic 乘子；士气损失不再除以沉着/威仪/忠义。属性 90 对 50 的同兵力杀伤比从 1.2–1.4 收窄到 1.00–1.06，差别改由时机体现：同一天刚下新命令时，带兵/布阵 40 的部队当天就绪 0.63，95 的 0.71；两万人新命令整理 带兵 30 要 14.5 小时，带兵 95 要 4.8 小时。

## 3. 已接好的调用（不依赖缺失脚本的部分）

- `campaign_state._execute`：命令类型变化时 `Process.issue_order(army, {"terrain", "action"})`。
- `campaign_state._upkeep`：每日先 `Process.end_day(army)` 结转延迟。
- `campaign_state` 道路追击：`Process.pursuit_rate(pursuer, fleeing)`（含善退、追击特性），双方各一条署名军报。
- `campaign_state` 违令概率：加 `Conduct.dissent_shift(officer)`（刚愎 +5pp），仍受规则上限。
- `siege_system` 准备度：`Process.engineering_rate(force)`（工事特性 −5% 工时）。
- `tactical_battlefield`：疲劳、光环改用 `Process`。
- `baseline_policy`（v6 权重）：
  - 七个人格因素基础权重改为非 0，主轴系数 0.25，人格 90 对 30 相差 15 分；
  - `engage`：协同友军未就位（`operation.support_id` 非空且 `operation.support_ready` 不为真）时扣 `commit_readiness × 20`，急躁者要求就位度 0.3（常人 0.8），更早投入；
  - `engage`：建议目标加分按 `advice_adoption` 缩放（刚愎打 0.73 折）；
  - `pursue`：`army.pursuit_steps + 1` 超过本人 `pursuit_limit` 才扣分（贪功上限 4、追击疏算 3、常人 2）；
  - `withdraw`：组织危机阈值加 `disengage_shift`（恋战 −15，怯战 +20，风险承受每偏离 50 一半 ±8）；
  - `support`：主副关系表移到 `policy_weights.support.relation`（同袍 +6、猜忌 −6、宿怨 −12）。
- `agent_adapter`：发给模型的 `officer` 改为 `Explain.model_profile(officer, context.members)`：核心定义、生效特性、同军团关系。
- `army_inspector`：判断栏追加 `Explain.intent_text(army, ctx, card)`。

## 4. 新增的部队字段约定

| 字段 | 谁写 | 谁读 | 含义 |
|---|---|---|---|
| `army.trait_ids` | campaign_state（加载/出征/接任）、army_corps（分队） | registry、process、conduct | 生效特性 id |
| `army.order_delay_hours` | `Process.issue_order` | `Process.readiness`（combat 出力）、面板 | 新命令剩余整理时间 |
| `army.pursuit_steps` | **unit_brain / tactical（本地补）** | baseline_policy `pursue` | 本次追击已追了几步，脱离接触时清零 |
| `operation.support_ready` | **unit_brain / tactical_plan（本地补）** | baseline_policy `engage` | 指定协同友军是否已到位 |
| `army.last_decision_source` | **决策记录处（本地补）**，模型选择时写 `"model"` | `Explain.intent` | 面板理由标［模型］ |

## 5. 你在 Windows 本地需要加的调用

以下文件在本仓库快照里缺失，我没有改它们。按需在对应位置加一两行即可；每条都可以单独加，互不依赖。

1. **unit_brain.gd / tactical_evaluator.gd：决策上下文带上人物**
   单位级上下文要能拿到主将人物字典（含 `personality`、`trait_ids`），`Conduct` 的人格偏移从 `officer.personality` 读，部队字典上没有人格。
   ```gdscript
   const Conduct = preload("res://scripts/officers/officer_conduct.gd")
   var officer: Dictionary = war.roster.officers.get(str(unit["officer_id"]), {})
   ```
2. **unit_brain：投入时机（急躁、好谋少决、骄矜）**
   主攻等侧翼时，用 `Conduct.commit_readiness(officer, {"enemy_renown_gap": 我方名望 - 敌将名望})` 作为“侧翼就位比例达到多少才投入”的门槛，并把结果写进 `operation.support_ready`。
3. **unit_brain / tactical_plan：追击深度（贪功、追击疏算）**
   每追一格 `unit["pursuit_steps"] += 1`，脱离接触时清零；停止条件用 `Conduct.pursuit_limit(officer)`。
4. **unit_brain：脱离（恋战、怯战）**
   接战中组织低于 `Conduct.disengage_line(officer)` 时转为脱离/后撤。
5. **unit_brain / officer_brain：敌情与伏兵（料敌、核报、多源研判、听辨、刚愎、言辞刻薄）**
   - 估计敌军兵力：`Process.estimate(true_strength, unit, rng, {"independent_groups": 来源数})`，rng 用独立种子流；
   - 伏兵：`Process.conceal_exposure(ambusher, complexity)` 抽暴露，暴露后 `Process.ambush_read(unit)` 抽识破；参军识破后主将以 `Conduct.advice_adoption(commander, adviser, {"lord_pride": 主将自尊})` 决定是否采纳；
   - 迎战：估计战力比低于 `Conduct.engage_ratio(officer)` 时不主动接战。
6. **unit_brain：原方案失效（应变、果决、过度负责）**
   收到“原方案失效”的情报或被伏击时，`Process.issue_order(unit, {"terrain": t, "urgency": u, "subcommanders_assigned": 有部将}, true)`。
7. **unit_brain：压力失误（沉着、令辞含混）**
   每次决策时 `pressure = 当日伤亡比例×6 + 被伏/被夹 0.3–0.5`，`rng.randf() < Process.pressure_error(unit, pressure)` 时本回合执行降级（如 hold 代替原命令，或扣 6 小时就绪）。
8. **tactical_battlefield / tactical_plan：侧击暴露（奇袭、穿插）**
   侧翼/奇兵行动进入可探测窗口时抽一次 `Process.conceal_exposure(unit, complexity, {"action": "flank"})`；未暴露的侧击可给一次突然性加成（加成值放 `campaign_rules.combat.flank`，不要放在人物侧）。
9. **army_corps 分队、corps_structure：命令下达**
   主帅给分队下新任务时同样调用 `Process.issue_order(child, ctx)`，`ctx.subcommanders_assigned = true`。
10. **report_policy.gd：署名军报不被合并**
    `Explain.signed()` 生成的军报以“某某某特性/属性：”开头。建议 `allow()` 对“遭遇追击/追击/武圣威压/小霸王连胜”与带署名的军报不做去重；对普通“交战”按部队按日合并，避免刷屏。
11. **officer_fate.gd 接任（主副关系，可选）**
    现在按 `corps.members` 顺序取第一人接任。可在候选里先排除与原主帅 `Dissent.relation(...) == "宿怨"` 的人。
12. **officer_page.gd 人物卡（可选）**
    `Explain.card(officer)` 返回 `{"suits": [...], "weak": [...]}`，可直接显示为“适合做什么/遇到什么会吃亏”。

## 7. 已知未达标与待复核

- harness 的 4 项未过：颜良/文丑只有 1 项指标显著不同（两张卡五维、人格几乎相同，靠特性只拉开投入时机）；过度负责、令辞含混只改命令整理 ±5%，代价稳定可测但不足 3%。若要它们可观测，需要在特性库 v1.1 里给这两条加一个更显著的流程分支，或放宽“普通 ±3–5%”上限，这是设计决定，留给你。
- 7 名人物卡面没有局限，局限按人格推定（`officer_traits.json` 的 `inferred`）：廖化、关凤、黄忠=恋战，关兴=贪功，张苞=急躁，张遵、周仓=追击疏算；袁熙的优势“守关轮值”按位置推定。
- MVP 编号特性（明令001 等）的具体机制在 Notion 特性库 v1.1 原文里，本次未能读到，按名称与 hook 注册表推定（`mechanism_basis: inferred`），请对照原文复核数值。
- 方案 M6 列的张郃、沮授、审配、许攸不在 `data/officers.json` 里，harness 改用现有 18 人与生成将。
