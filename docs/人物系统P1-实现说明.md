# 人物系统 P1：实现说明

分支 `feat/people-p1`（从 `feat/combat-officer-identity` 的 d087c7a 开出），2026-10-23。对应人物系统开发方案 v1 的 P1：01 数据模型、schema 6→7 迁移、事件总线、开局记忆、存档。战斗逻辑没有改动。

## 1. 文件

| 文件 | 作用 |
|---|---|
| `scripts/people/person_state.gd` | `PersonState`：一个人物的运行时状态，只存基本类型，`to_dict()` / `from_dict()` 原样序列化 |
| `scripts/people/person_store.gd` | `PersonStore`，Autoload **People**：全部人物、记忆/关系/印象/许诺/生平分表、开局、存读档 |
| `scripts/people/card_migrate.gd` | `CardMigrate`：schema 6→7 合并补丁、推定心志、卡 → `PersonState` |
| `scripts/people/memory.gd` | `PeopleMemory`：P1 只有 `seed()`（开局记忆与生平）和衰减公式 |
| `scripts/people/circles.gd` | `PeopleCircles`：圈子成员解析（名单或出身规则），P3 再加传播 |
| `scripts/people/people_events.gd` | `PeopleEventBus`，Autoload **PeopleEvents**：`emit()` 编号并广播，`drain()` 取本旬队列 |
| `scripts/people/rng.gd` | `PeopleRng`：key → SHA-256 → [0,1)，同 key 同值（R6） |
| `scripts/people/caps.gd` | `PeopleCaps`：属性点 ±6 / 相对 ±10% / 概率 ±5pp；bias 单来源 ±15、合计 ±30（R3、R4） |
| `scripts/people/people_validation.gd` | `PeopleValidation`：01 §5 校验规则，纯函数 |
| `tools/validate/validate_people.gd` | 校验命令行入口，有 error 退出码 1 |
| `data/people/*.json`、`data/people/guandu/*.json` | 人物系统 v1 数据（原样拷入，未改动） |
| `tests/people/*_validation.gd` | 单测，见第 6 节 |
| `tests/fixtures/people/guandu_seed_memories.preview.json` | `check_people_data.py` 的开局记忆预演，作为 seed 对齐基准 |

改动的已有文件只有两个：`project.godot`（注册 Autoload，People、PeopleEvents 排在 GameState 之前）和 `scripts/core/game_state.gd`（存档两处挂接，见第 4 节）。

脚本之间按仓库惯例用 `preload` 常量互相引用，不依赖 `class_name` 全局缓存，所以不开编辑器也能直接 `--script` 跑。

## 2. 开局数据流

```
People.load_scenario("guandu")
  ├─ OfficerRepository.cards()                       人物卡（schema 6）
  ├─ data/people/guandu/persons_s7.json               schema 7 补丁
  ├─ CardMigrate.migrate_all() → CardMigrate.to_state()   20 个 PersonState
  └─ PeopleMemory.seed(store, seed_events.json, memory_rules.json)
        → People.memories[id]、People.biographies[id]
```

- **迁移**：按 id 合并，旧字段不删；卡上已有值不覆盖；补丁也没有心志时按 `drives.json.infer_from_card` 推定并登记到 `inferred`；迁移两次结果不变。
- **全局旬号**：`(年×12 + 月−1)×3 + 旬−1`。开局旬号取 `seed_events.json.start`（建安五年二月上旬，数据里注明是假设）。
- **开局记忆**：每条前史事件按 `memory_rules.events[kind]` 给每个接收方写一条记忆，强度 `max(base − base×r×经过旬数, base×floor_ratio)`，不超过 `drop_below`（3）的不写；重档保底 base×0.4。接收方只取在场人物，对象就是自己的跳过。`witnesses`、`rivals_same_post` 需要同城同军、同岗位的运行时上下文，开局跳过（与 Python 预演一致）。规则的 `if` 目前只有 `data.<键> != ''` 一种写法，遇到别的写法会断言失败。
- **不乘性格系数**：P1 与预演一致，记仇、自尊等系数在 P3 的 `ingest()` 里加。
- **生平**：`bio=true` 的事件写进当事人和 `data.bio_also` 里在场人物的生平。

| `runtime_officer()` 桥接 | 未做 | 要改 `officer_context.setup()` 的取数来源，属于战斗侧接入，留到需要成长/伤病影响战斗时 |
| 关系边 | `People.relations` 只建表、存读档 | 卡上 `relations[].to` 是人名不是 id（见第 7 节第 1 条），P3 再定 |

| 开局触发 | 没有在游戏流程里自动调用 `People.load_scenario()` | 世界剧本从 191 年 9 月开局，人物卡与前史是 200 年官渡快照，何时 seed 需要你定（第 7 节第 11 条） |

## 4. 存档

主存档 `user://city_campaign.json`（`GameState._save()` / `_load_save()`）多一个 `people` 键，存档 `version` 仍为 3：

```jsonc
"people": {
  "people_version": 1, "scenario": "guandu", "xun": 7203, "next_mid": 20,
  "persons": {"<id>": PersonState.to_dict()}, "relations": {}, "memories": {"<id>": [MemoryEntry]},
  "impressions": {}, "promises": {}, "biographies": {"<id>": [{eid, year, month, kind, tag, text}]},
  "events": {"seq": 0, "pending": []}      // PeopleEvents 未结算的事件队列
}
```

- 读档：`People.import_state()` 认版本，不认识时保留当前状态并返回 false；成功后再还原 `PeopleEvents`。
- 没有 `people` 键的旧档不动人物系统。
- 圈子定义和不上场人物不进存档，按 `scenario` 重读。
- 战斗测试快照（`battle_snapshot`）不含人物系统；P1 战斗不发人物事件，不受影响。

## 7. 数据与设计里发现的问题

1. **人物卡关系边用人名**：`data/scenarios/guandu/officers.json` 的 `relations[].to` 写的是人名（如某人的长子），不是 id；方案说「关系边仍用卡上已有 relations」，但按 R1 代码不能拿人名去对。需要改成 id（不上场的人用 `offstage.json` 的 `off_*`）。
2. **势力是显示名**：人物卡 `faction` 是「某某集团」这样的名字，世界剧本 `scenario_world_demo.json.factions` 用 `cao_cao` 一类 id，两边对不上；`PersonState.faction` 暂存显示名，势力型心结对象也只能按显示名校验。
3. **城池 juancheng 不在地图数据**：`persons_s7.json` 中 `cc_004.knots[0].object` 和 `seed_events.json` 的 `seed_032.target`。Python 校验里城池表是写死的 `{"juancheng"}`。要么地图补这个城，要么换成地图上有的城。
4. **词条库缺失**：`check_people_data.py` 引用的 `../traits/{xixing,lvli,xinjie,shengming}.json` 不在仓库，`data/officers/traits.json` 只有 `trait_*` / `flaw_*` / 专属特性。所以校验第 1 条只能查格式、第 5 条做不了，推定心志里「学问类习性」只能按无计。
5. **心志推定公式与补丁差得多**：用 `drives.json.infer_from_card` 推 20 人，首位心志与补丁一致的只有 5 人；「安身」普遍偏高（来自 `损失厌恶`）。`ys_003` 在 `inferred` 里登记了 `drives`，补丁写的是功名/忠义，公式得出天下/安身。公式第二项门槛 0.15 几乎总能过，推不出单条心志，而补丁里有 3 人只有一条。
6. **记忆 kind 没有衰减档**：`memory_rules.json` 会写出 `city_lost`、`kin_punished`、`passed_over`、`saw_injustice`、`accepted_surrender`，但 `weight_class` 里没有，按缺省中档处理（与预演一致）。
7. **事件枚举与规则表不一致**：00 §6 的枚举有 `betrayed_by`，`memory_rules.events` 没有；规则表有 `jailed`，枚举没有。
8. **心志规则引用了没有来源的事件**：`drives.json.rules[].on` 有 17 种既不在 `memory_rules.events` 也不在 00 §6 枚举里（`idle_xun`、`entrusted`、`lord_misdeed`、`consulted`、`fined`、`kin_captured`、`city_besieged` 等），P2 需要定它们由谁发出、是不是按旬自动产生。
9. **关系规则没覆盖的记忆**：`relation_rules.from_memory` 不处理 11 种会被写出的记忆（`battle_lost`、`ally_killed`、`lord_died`、`defected`、`surrendered_to`、`saw_defeat` 等），这些记忆不会改变关系。若是有意的，建议在数据里注明。
10. **开局记忆偏少**：中档 r=0.04，25 旬（约 8 个月）衰减到 0，所以一年以前的被谮、被驳、受任全部清空。开局只有 19 条记忆、11 人有记忆，主公、许攸、审配、张郃等 9 人开局零记忆。如果希望谋士之间的旧怨带进开局，需要调档或给关键前史事件单独定档。
11. **开局时间线冲突**：`GameState` 的世界剧本从 191 年 9 月开局，人物卡与前史是 200 年官渡快照（`seed_events.json.start` 也是假设值）。需要你定：哪个剧本、在哪一步调用 `People.load_scenario()`。
12. **圈子类别**：`circles.json` 的 `circle_qiaopei` 按出身郡规则入圈，类别却是「宗族」；README 说同乡 1 个、宗族 2 个，与这条的含义对不上。
