# 战斗系统扩展设计（地形 / 阵型 / 单挑 / 战况可读性）

更新：2026-10-04。范围：现有战略道路交战、小沛六角战场、围城系统之上的四项扩展。
实现：2026-10-05，见 [实现与验证记录](战斗系统扩展实现-2026-10-05.md)。下文地形码示例是核对前的候选；实际码表已按原始标字地图修正。用户已确认“川格不可通行，仅浅滩可渡”，共享全局 blocked 集新增码 13。
边界沿用 `docs/战斗人物属性接入.md`：部队级战斗、一格一日、人物原始数值不叠加、新增数值均为**可调的原型平衡参数**。
每项系统交付时都配一个独立 `tests/*_validation.gd`，并回归既有战斗测试。

---

## 总览与优先级

| # | 系统 | 一句话目标 | 依赖 | 改动量（原型） |
|---|---|---|---|---|
| 1 | 地形 | 让六角战场的每格地形真正参与结算与走位 | 无（零件已就绪） | 1–2 人日 |
| 2 | 阵型 | 给军团加"编制"维度：鱼鳞/鹤翼/方圆/雁行/锋矢/长蛇 | 与地形联动更佳 | 2–3 人日 |
| 3 | 单挑 | 名将对决：触发/接受/判定/结果，影响士气与将领状态 | 独立；建议在军报框架后 | 2–3 人日 |
| 4 | 战况可读性 | 优势条 + 军报因子解释 + 会战总结 | 与 1/2/3 互相供数 | 1–2 人日 |

建议实施顺序：**地形 → 战况可读性（并行）→ 阵型 → 单挑 → 合并全量回归**。

命名注意：`army_corps.gd` 既有 `formations` 字段表示"军团编制列表"（分队名册），与本文"阵型"无关；新键统一用 `corps["formation"]`（未设置时视为 `"none"`）。

## 一、地形系统

### 1.1 现状与问题

- 战术层 `tactical_battlefield.gd` 的 `resolve()` 两处固定传 `"plains"`（约 374/394 行）：小沛窗口实测 10+ 种地形码（1/2/3/4/5/8/9/10/13/15/16…）**全部按平原打**。
- `map_grid.bin` 的地形码（字节 0）尚无"战斗类别"映射表；当前只有可通行/不可通行两分（blocked = {0,10,11,14,19,22,23}）。
- 战略层 `war._terrain(node)` 已按州区映射（mountains/hills/river），`officer_battle` 里水练、险地用兵、骑兵地形减益均已写好——战术层只差接线。
- 原版口径（`docs/军队移动核对.md`）："地形影响移动速度。干道移动快，森林、山地和河川移动慢，险山、悬崖及急流无法行进。"

### 1.2 战斗地形类别（6 类 + 回退规则）

| 类别 | 战斗效果（原型） | 说明 |
|---|---|---|
| `plains` 平地/农田 | 无修正（基准） | **未识别码一律回退到本类**（行为与现状一致，安全降级） |
| `forest` 森林 | 防御 +10%；骑兵攻击 ×0.9；远射（支援/抛射）伤害 ×0.85 | 火攻预留（本次不做） |
| `hills` 丘陵 | 防御 +8%；骑兵攻击 ×0.95 | 险地用兵特性沿用 |
| `mountains` 山地 | 防御 +15%；骑兵攻击 ×0.8；容量系数 0.6（已实现）；**进入当日攻击 ×0.85**（迟滞） | 险地用兵特性沿用 |
| `river` 河川 | 不可通行（保持 blocked，现状） | 过河只发生在渡口 |
| `ford` 渡口 | 可通行；骑兵攻击 ×0.8；水练修正按 `river` 处理；**当日渡过不可攻击**（只在渡口格生效） | 跨河唯一通道 |
| `marsh` 湿地 | 全员攻击 ×0.9；骑兵 ×0.85；疲劳 +2/日 | |

数值全部写入 `data/war/campaign_rules.json` 新节 `terrain`，运行时读取，便于调参和跑测。

### 1.3 地形码 → 类别映射（先行核对）

新增 `data/war/terrain_table.json`：

```json
{
  "note": "地形码→战斗类别。未列出的码回退 plains；blocked 集保持现状。",
  "codes": { "8": "forest", "9": "forest", "15": "ford", "16": "ford", "13": "marsh" },
  "default": "plains"
}
```

核对流程（唯一前置工作）：

1. 工具：`tools/terrain_code_audit.py` —— 统计每个地形码的全国格数与样例坐标（输出 json）。
2. 对照：2D 地图"地形版"与 3D 地表截图逐码核对（步 1 的样例坐标可直接跳转截图）。
3. 结论回填 `terrain_table.json`；未核对完的码自动落回 `plains`，机制可先行开发，映射随核对补齐。

### 1.4 接线点（代码）

| 位置 | 改动 |
|---|---|
| `combat_system.gd power()` | 骑兵地形因子从 `["mountains","river"]` 粗判改为读 `terrain` 节字典（plains/forest/hills/mountains/ford/marsh） |
| `combat_system.gd losses()` | 容量系数扩到 `mountains`（0.6 已实现）；新增 `forest` 远程削弱（当 attacker 为纯弓）、山地/渡口迟滞乘子 |
| `officer_battle.gd unit_attack/defense/march_speed` | 新增 `forest`/`marsh`/`ford` 分支；`ford` 走水练修正（与 river 同管道） |
| `tactical_battlefield.gd` | 新增 `terrain_class(cell) -> String`（读表）；`resolve()` 两处 `"plains"` 改为：近战取**防守方所在格**、远射取**目标格**；`move()` 进入 mountains/ford 时置 `tactical["terrain_delay"]=true`（当日攻击 ×0.85），次日清除 |
| 军报 | 战斗条目附地形名（如"在森林承受攻击"），供战况可读性复用 |

### 1.5 验证 `tests/terrain_battle_validation.gd`

- 映射表覆盖：blocked 之外出现过的码要么有归类、要么回退 plains（断言工具输出）。
- 同兵种同将领、只换格子的对照战：forest 防守方损失 < plains 防守方损失；山地骑攻 < 平原骑攻。
- 渡口：同日渡河部队攻击无效/减伤；次日恢复。
- 迟滞：进入山地当日攻击乘子生效、次日清除。
- 回归：`tactical_battlefield / encirclement / siege_corps / battle_discipline` 不回归。

后续（本设计不含）：一格一日改"移动力"。若要贴原版"森林山地慢"，先出移动力方案再动，避免破坏围城与军纪测试的节奏假设。

## 二、阵型系统

### 2.1 目标与边界

- 每军团一个**主阵**（`corps["formation"]`），全军分队继承；与 `deploy_by_commander` 的 posture（分兵比例）正交叠加。
- 阵型是"编制"层：影响正面接敌、侧翼抗性、兵种发挥、地形适配；不做升级树、不做单兵编制。

### 2.2 阵型表（6 种，原型参数可调）

| 阵型 | 定位 | 加成 | 代价 | 适配场景 |
|---|---|---|---|---|
| 鱼鳞 | 正面突击 | 正面攻击 +10% | 被侧击时受伤 +15% | 平地、正面推进 |
| 鹤翼 | 包抄 | 侧击加成 +12%（含 flank 乘子 1.15→1.27） | 正面防御 -8% | 兵力优势、追求包围 |
| 方圆 | 守势 | 受伤 -12%；脱离准备需求 +1（难被牵制） | 攻击 -12% | 守城、等援、迟滞 |
| 雁行 | 弓阵 | 远射伤害 +15% | 近战防御 -10% | 弓兵占比高的军团 |
| 锋矢 | 突破 | 接敌后前 2 日冲击 +18%，第 3 日起 +5% | 防御 -5% | 精兵斩首、速战 |
| 长蛇 | 机动 | 山地/森林受伤 -8%、迟滞免疫 | 正面攻击 -8% | 山地行军、撤退掩护 |

生效系数 = 表值 × 熟练度系数 `clampf(0.7 + 布阵/200, 0.7, 1.25)`（与现有 command 系数同风格；主将"布阵"越高越吃满收益）。

### 2.3 机制

- **选择**：① 部署时随 `deploy_corps` 一起指定（主帅决策新增 `formation` 字段）；② 战中军令 `set_formation`（新增 order 类型）。
- **变阵成本**：组织 -10，当日不可攻击/移动，冷却 3 日；接战中变阵额外 -5 士气（急促换阵）。紧急指令（`rear_guard`/`regroup`）不受冷却限制（沿用现有军令豁免风格）。
- **主帅决策**：`commander_context` 增加 6 个 `set_formation` 候选与简述（敌兵种构成/地形/我军兵种比例作为提示）；prompt 增补"阵型适配"说明；后台决策管线（`decision_scheduler`）自动复用，无新机制。
- **耦合**：`tactical_battlefield.resolve()` 的侧击乘子与敌方阵型联动（鹤翼强化、鱼鳞被克）；方圆在"被包围"判定中 `required_preparation` +1；雁行与支援射程（3 格）联动时伤害加成只对 `stop_distance > 1` 的攻击生效。
- **存档**：`corps["formation"]`、`formation_changed_at`、变阵进度入存档；旧档缺省为 `"none"`（等价当前行为）。

### 2.4 界面

- 军队详情与军报显示当前阵型与熟练度系数；
- 出阵界面（`dispatch_view`）第二阶段加"阵型"下拉（玩家编队默认阵型），MVP 先只读展示。

### 2.5 验证 `tests/formation_validation.gd`

- 加成生效：同兵对打，鱼鳞正面 > 无阵；被侧击时鱼鳞受损 > 无阵（克性成立）。
- 变阵成本：组织扣减、当日封锁、冷却、紧急豁免。
- 熟练度：布阵 50 vs 100 的系数差在预期区间。
- 存档：阵型与大势恢复；旧档回退 `none`。
- 决策：`commander_context` 候选合法率 100%（`tests/decision_scheduler_validation.gd` 模式）。

## 三、单挑系统

### 3.1 目标与边界

名将时刻：接战触发的武将对决。**不改兵力、不秒杀部队**；产出士气/组织波动、将领负伤与叙事。刀术/枪术/护主/个人兵器仍属另案（见 `战斗人物属性接入.md` 边界）。

### 3.2 触发

- 条件：两队相邻（格距 1）、至少一方 `action ∈ {engage, continue}`（正面近战，远射不触发）、双方均非撤退、每对将领每战限一次、每将每战最多 2 次、当日每对最多一次。
- 发起判定（每日结算前）：
  `P = 0.12 × 战况修正 × 性格修正`
  - 战况：发起方处于劣势（战力比 < 0.8）×1.5；优势 ×0.8（稳者不赌）。
  - 性格：`风险承受 ≥ 70` ×1.3、`自尊 ≥ 70` ×1.3、`自制 ≥ 70` ×0.8、`耐心 ≥ 70` ×0.85。
  - 名望差 ≥ 20：弱者不发起（×0.3）。
- 接受判定（被挑战方）：
  `P = 0.55 × 性格修正`
  - `忠义 ≥ 70` ×1.2、`自尊 ≥ 70` ×1.25（"若遭名将挑战不易避"——颜良类人设）、`自制 ≥ 70` ×0.85；己方明显劣势时 ×0.8（保存实力）。
  - 拒战：挑战方 -6 士气、被挑战方 -3；不再对同一对手重复。
- 触发与结果写军报（标题"单挑"），复用 `combat_effects_3d` 的斩击/火花特效作表现起点。

### 3.3 判定（三合制）

- 战力值 `D = 武艺×0.5 + 膂力×0.3 + 体魄×0.2 + (骑术×0.1 若骑兵) + 威仪压制修正(±5%)`，`skill()` 的 100+ 递减沿用。
- 每合取值 `D + rand(-15, +15)`（战斗 RNG 种子统一入档，保证可复盘）。
- 三合两胜；1:1 后第三合决胜；全平为"平手"。
- 文案模板：斩 → "大战三十合，[甲]刀劈[乙]于马下"；胜 → "[甲]技高一筹，[乙]败退本阵"；平 → "鏖战百合，不分胜负"。

### 3.4 结果与效果（原型）

| 结果 | 部队效果 | 将领效果 |
|---|---|---|
| 斩（2:0） | 敌方部队士气 -25、组织 -15；我方士气 +8 | 敌将负伤：战后 `recovering` 10 日 |
| 胜（2:1） | 敌士气 -12；我方 +5 | 无 |
| 平 | 双方 ±3 | 无 |
| 拒战 | 挑战方 -6，被挑战方 -3 | 无 |

- 将领负伤落地：单挑时该部队打 `duel_wounded` 标记；`on_finish`/`_finish` 结算时若仍有标记 → `officer_states[officer] = {"status":"recovering","available_after": tick+10}`；部队战斗中保留"带伤指挥"（该部攻击 ×0.9，可选项）。
- 与"武圣威压"（`first_contact`）互斥同日叠加：同日已触发威压则当天不再触发单挑（防止名将双重惩罚）。
- 阵亡开关：默认关闭（只负伤）；军事化开关留给调参。

### 3.5 验证 `tests/duel_validation.gd`

- 触发条件：远射不触发、撤退不触发、每对战一次、每将上限。
- 接受修正：自制高者拒战率上升、自尊高者接受率上升（固定种子抽样断言区间）。
- 判定：固定种子下结果可复现（复盘基础）。
- 效果：士气/组织扣减在表值 ±1；负伤衔接 `officer_states`；不与武圣同日叠加。
- 存档：负伤、对战记录（`battle_contacts` 式）随军入档。

## 四、战况可读性（战斗反馈）

### 4.1 三层交付

**A. 战斗内——优势条与飘字**

- 顶部优势条：`advantage(faction) = Σ strength × (0.5 + morale/200) × (0.5 + organization/200) × formation_factor`，双方归一化显示（0–100%）；让玩家一眼看出"谁在压谁"。
- 每日损失数字：3D 战场飘字（复用 `combat_effects_3d` 的 billboard 管道），只对视野内接触显示，上限 6 条/日。
- 实现位置：`army_world_3d` 的 HUD 层新增"战况条"，数据直接读 `war`（无新状态）。

**B. 军报——因子解释**

- 每条战斗军报附 1–2 条关键因子文案（确定性生成，模型不参与）：
  - 从 `combat_system` 新增 `power_breakdown(army, rules, terrain) -> Dictionary`（返回 base/士气/训练/军备/组织/疲劳/指挥/兵种克性/地形/阵型各乘区）。
  - 取对结果影响最大的两区，生成如："敌军据守森林（防御 +10%），我军骑兵受限（×0.9）"、"敌军士气低落（42），输出仅六成"。
- 阈值：乘区偏离 1.0 超过 0.05 才进入候选，避免啰嗦。

**C. 战后——会战总结**

- 新状态 `battlefield["log"]`：每 tick 一条 `{tick, sides:[{faction, strength, morale, org}], losses, events[]}`（events：侧击/单挑/破墙/溃败/援军阻断），上限 240 条，随存档。
- 军报页新增"会战总结"卡（`campaign_ui._build_reports` 扩展）：
  - 摘要行：持续日数、胜负、双方阵亡/伤/俘、单挑与斩将、夺城/缴获；
  - 时间线表：按日列出兵力/士气/当日损失/事件（读 `battlefield["log"]`）；
  - 导出按钮（可选）：调用现有轨迹工具（`tests/battle_motion_trace.gd` 同源逻辑）生成 JSON 供外部分析。
- 守恒断言：`初始 = 剩余 + 阵亡 + 伤 + 俘 + 归队`（复用既有账本，总结页直接展示）。

### 4.2 验证 `tests/battle_feedback_validation.gd`

- 优势条：随兵力/士气变化单调（构造三组状态断言排序）。
- 因子文案：地形 ≠ plains 时必出地形因子；士气 < 50 时必出士气因子；无显著因子时输出空（不硬凑）。
- 会战总结：守恒等式成立、日志上限、事件记录完整（侧击/单挑/破墙至少各触发一次夹具）。
- 存档：`battlefield["log"]` 往返一致。

## 五、实施顺序、风险与回归

1. **地形**（先做）：`terrain_table.json` + 规则节 + 四处接线 + `terrain_battle_validation`。
2. **战况可读性 A/B**（可并行）：`power_breakdown` + 优势条 + 军报因子文案。
3. **阵型**：数据节 + `set_formation` 军令 + 决策候选 + 军报呈现 + `formation_validation`。
4. **单挑**：`duel_*` + 负伤衔接 + `duel_validation`。
5. **会战总结 C**（串起前面所有事件类型）。
6. **回归清单**：`tactical_battlefield / encirclement / corps / siege_corps / battle_discipline / decision_scheduler / global_battle_grid / officer_battle / xiaopei_battle` 全绿 + `xiaopei_campaign_run` 多随机种子跑测（胜负天数分布无退化）。

风险与注意：

- 工作区当前有大量未提交改动（并行开发合并态）——**开工前先建立一个提交点**，避免冲突与丢失。
- 所有新参数集中在 `data/war/campaign_rules.json`（`terrain` / `formations` / `duel` 三节），不散落在代码里。
- 命名冲突守卫：`formations` 旧义（编制列表）不动；新义用 `corps["formation"]`。
- 小数据清理（顺手）：`data/officers.json` 中"臂力"与规范名"膂力"混用（4 处文本 vs 16 处），建议统一为"膂力"（不影响数值，只影响文本一致性）。
