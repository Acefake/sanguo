# 用户大地图素材接入

原始十张图片保存在 `assets/map/supplied`。当前浮雕地图使用 `composite.png` 左上角 1920×1080 底图和同一张图集内的 51 块灰白地形。`region-edge-b.png` 对应这一版轮廓；黄色 `region-edge-a.png` 与水墨图是另一套版本，不能混合拼接。

地图轮廓来自合集右上的完整边界图，裁切范围为 `(1920,0)-(3430,1055)`，放置在底图 `(100,0)`。`tools/assets/build_supplied_blocks.py` 通过轮廓匹配记录每块的源图集切片，再按明确的控制城市表装配。

原始粗描边的两侧内缘不能当作两条独立城市边。装配时将描边带归并成共享边界，输出原尺寸分块纹理与 `world-shared-boundaries.png`；每个像素只属于一块，边线统一绘制一次。透明纹理按地块的原尺寸生成，不再单独缩放遮罩；源图集黑底向外补齐边缘颜色，防止采样产生黑色内缘。

51 块各有一座控制城。保留 70 城、2 关和 13 州的数据，另外 19 城属于已有分块，放大后显示。势力填色取控制城的归属；辅助城市的城务和数据保持独立。坐标属于游戏美术布局，不是历史测绘。

重新装配：`python tools/assets/build_supplied_blocks.py`。源文件已经归档，不需要临时附件。修改城市绑定时编辑脚本中的 `CONTROLLERS`；不要运行旧 `build_world_map.py` 覆盖新版数据。

检查：`python tests/world/map_seam_validation.py` 验证所有分块在共享画布中无重叠和丢失像素；Godot 的 `tests/world/map_blocks_validation.gd`、`tests/world/map_validation.gd` 和 `tests/city/city_validation.gd` 验证纹理、城市位置、控制城归属同步、通路及城市往返。
