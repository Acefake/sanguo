# 自主战争首版：使用与验证

实现与核对日期：2026-10-04。设计依据为《武将智能体自主战争方案》。当前首版运行于二维全国战略地图；三维战争表现、完整粮道运输、多岗位协作和人物长期成长属于后续阶段。

## 使用

1. 运行项目，默认进入二维全国战略地图。
2. 单击目标据点，在右侧城池面板点击 **派遣武将**。
3. 选择当前势力、出发城和主将。首版提供刘备、袁绍、孙坚三个具有现成人物档案的演示势力；执行任务期间不能切换当前势力。
4. 查看自动配兵、携粮、留守与预估行程，点击 **派遣**。敌方目标是攻取任务，本方目标是守援任务。
5. 使用左上角 **进行一日** 或 **推进本月** 推进战争。收到重要军情时，本月推进会提前停止。
6. 在 **军情** 中查看报告；军报有发出和收到时间。点击已完成军队的 **查看战役复盘**，查看当时情报、粮草、士气、选择与依据。

玩家不直接控制路线、接战、侦察、追击或撤退。可同时派出不同主将，军队同场接敌时援军参与结算。城池归属发生变化后，地图颜色与城内资源同步更新。

地图军队标记使用最近收到的军报位置，可能已经过时。开始派遣后，敌城详情与悬停不再显示实时库存，只显示已送达的侦察估计；玩家不能进入敌城执行内政。主将可知情报与世界真相分开保存。

## 模型服务设置

从 **军情 → 模型设置** 打开配置：

| 字段 | 填写内容 |
|---|---|
| 启用模型自主决策 | 配好服务后打开 |
| 接口地址 | 完整 Chat Completions URL，例如本地兼容服务的 `http://127.0.0.1:11434/v1/chat/completions` |
| 模型名 | 服务实际提供的模型 ID |
| API 密钥 | 云端服务要求的密钥；本地服务可留空 |
| 等待上限 | 单次请求超时，2–60 秒，默认 15 秒 |
| 同时请求武将数 | 1–12，默认 6 |
| 每个游戏日总等待上限 | 2–30 秒，默认 8 秒；超时未返回者由本地策略接管 |
| 关闭模型思考 | 仅对 OpenRouter 端点生效；其他服务应选择本身非思考的模型 |

点击 **保存设置**。接口地址、模型名、启用状态、等待上限、并发数、每日等待上限、思考开关与密钥均保存到 `user://officer_agent.cfg`，重启后自动加载；密钥栏以掩码显示，密钥仅保存在本机配置文件，不写入游戏存档。

智能体接收结构化人物、任务、己军状态、已知敌情与候选行动，返回：

```json
{
  "candidate_id": "候选行动中的id",
  "reason_summary": "一句简短的决定依据"
}
```

这是首版的实际接口。方案中更自由的多步工具协议可以在后续扩展。模型的选择真实决定下一行动；其文字不能直接创建兵粮、改变归属或决定战损。

没有配置模型时使用本地人格策略，界面明确显示 **本地策略**。连接失败、超时、非法 JSON 或非法选择时同样接管。请求按“同时请求武将数”滚动发出（默认 6），整个游戏日的等待不超过“每个游戏日总等待上限”（默认 8 秒），未及时返回的武将改由本地策略接管；同一日的观测先统一生成，结果收齐后再提交，等待网络时不会额外推进战争。

稳定行军期间沿用计划，在路线/敌情/资源风险变化时重判，另有每三日一次复查。每位主将最多每天一次模型决策，原方案中的战斗内多次重判尚未实现。

## 已实现规则

- 驻军自动动员，保留守军与城内储粮；主将出征后被占用，不能重复派遣。
- 旧驻军迁为步兵；新征兵在训练达标后可包含弓兵、军备达标后可包含骑兵。演示截图中的混编军队来自独立测试配置，不改变玩家存档。
- 按路线成本与带兵能力推进行军，道路中的敌军相遇不会直接交换位置穿过。
- 当前道路据点代表城池附近的战略接点，军队可以经过敌方地区；经过本身不改变城池归属。第一版自动组织目标城守援，不模拟全部势力自主发起的战争。
- 兵种、训练、装备、部署、地形、组织和疲劳影响战斗，双方损失从同一时点状态计算。
- 士气或组织崩溃触发撤退，追击造成被俘损失，缺粮影响组织与士气。
- 友城补给实际扣除库存；驻军与携带的伤兵也消耗粮草，月结不再重复扣除驻军口粮。
- 围城消耗守军、积累攻城准备；满足占领条件后更新归属、留驻兵力并结束任务。
- 归营时回收存活兵员与剩余携粮，伤兵进入城池；月结恢复部分伤兵。
- 保存版本升级至 2，兼容原版本 1；军队、任务、私人观测、军报、决策与随机状态一并保存。
- 采用临时文件完成后替换存档，避免在写入中间状态时直接覆盖原文件。

战斗当前每游戏日一次结算；完整水战、独有特性的战斗触发、多岗位将领协作、叛变/拒令、运输队和伤兵按原兵种恢复尚未实现。部队覆没的将领暂按恢复状态处理，不模拟完整生死与俘虏交涉。

人物能力来自现有设计卡，不代表191年每位人物的历史年龄与任职状态。时间采用每月30日的游戏日历，路线、地形修正和兵种系数是可调演示参数。

## 代码入口

- `scripts/game_state.gd`：日期、城务月结、粮食消耗、版本2存档。
- `scripts/war/campaign_state.gd`：派遣、军队状态、决策调度、观测、补给、接敌、围城、归营和军报。
- `scripts/war/map_graph.gd`：共享路线与通行查询。
- `scripts/war/combat_system.gd`：兵种战斗、同场军队合并与损失账本。
- `scripts/war/campaign_ui.gd`：派遣、报告、复盘和设置界面。
- `scripts/agents/officer_context.gd`：标准子属性、14人格轴、势力映射。
- `scripts/agents/baseline_policy.gd`：人格驱动的基础策略。
- `scripts/agents/agent_adapter.gd`：兼容接口、批量请求、错误处理与取消。
- `data/war/campaign_rules.json`：动员、兵粮、路线、兵种和势力映射参数。

## 验证

以下检查由 Godot 4.7.2 执行；测试使用独立进程或独立存档，不推进玩家的真实战役。

| 检查 | 覆盖 |
|---|---|
| `tests/war_validation.gd` | 派遣预览、重复派遣、权限、兵粮守恒、私有情报、14人格轴、模型选择改变动作、道路接敌、援军参战、围城、撤退归营、版本迁移、随机状态恢复、断线接管和人格偏好 |
| `tests/war_agent_http_validation.gd` | 实际 HTTP 请求、并发批次、请求与结果对应、耗量统计、非法JSON、HTTP503、超时、取消与迟到结果隔离 |
| `tools/validate_war_agent_http.py` | 临时本地测试服务器，返回模拟响应，结束时关闭；没有调用真实模型或收费服务 |
| `tests/capture_war_preview.gd` | 实际图形渲染下的派遣、自动战役、军报与模型设置检查，以及界面截图 |
| `tests/war_month_performance_validation.gd` | 本地月度推进分帧、全程操作锁、重复请求、单次存档、军报刷新缓存、逐日/月度状态一致、空闲月结和重要军情暂停；如存在玩家存档，只读取副本，使用临时测试文件保存 |

自动战争测试中的一支6000人军队在16个日结步骤内完成攻取，相关账本检查通过。这个结果是固定演示条件下的测试，不代表全地图平衡已经校准。

已有城务与地图检查作为回归测试，确认征募、交易、保存、城内往返、全国路线与归属显示仍然工作。真实模型测试见下节。

### 模型服务实测（2026-10-04）

用游戏同款决策请求（约 1.5k token 中文上下文、要求简短 JSON）在硅基流动实测，并通过游戏真实链路完成 18 将批测（并发 6）：

| 候选模型 | 单次延迟 | 18 将整批 | 说明 |
|---|---|---|---|
| `Qwen/Qwen3-30B-A3B-Instruct-2507` | 0.9–1.3 秒 | 约 4–6 秒，18/18 合法、0 回退 | **当前选用**；本身非思考 |
| `inclusionAI/Ling-mini-2.0` | 0.7–1.1 秒 | — | 更快但决策偏保守 |
| `deepseek-ai/DeepSeek-V4-Flash` | 2.4 秒起，偶发 60 秒以上 | — | 思考不可控 |
| `Qwen/Qwen3.5-35B-A3B` | 1.1 秒（关思考）/ 14.5 秒（默认） | — | 默认开思考 |
| `Qwen/Qwen3.5-9B`、`stepfun-ai/Step-3.5-Flash` | 60–78 秒 | — | 默认思考，太慢 |
| `Qwen/Qwen3.5-4B` | 请求超时 / 503 | — | 免费但当时不稳定 |

- 本游戏只对 OpenRouter 端点发送“关闭思考”参数；其他兼容接口应选择**本身非思考**的模型。
- 当前配置：`https://api.siliconflow.cn/v1/chat/completions` + `Qwen/Qwen3-30B-A3B-Instruct-2507`；等待上限 15 秒、并发 6、每日等待上限 8 秒（可在模型设置中调整）。
- 计费（硅基流动现价）：输入 ¥0.7 / 输出 ¥2.8 每百万 token；单次决策不足 ¥0.001，18 将整批约 ¥0.01。
- 游戏正在运行时，重启游戏后可加载新配置。

### 月度推进性能修复（2026-10-04）

本地策略立即返回，`await` 本身不会让出一帧。原先月度循环在同一帧内连续执行日结，每天两次发布完整刷新、重新创建军报控件和系统字体，并重复保存完整战役。修复后复用楷体字体及字形缓存，按日让出帧、全程保持操作锁，只更新推进状态；结束或重要军情暂停时统一保存和刷新军报。收到的军报没有变化时复用现有界面，地图同帧刷新也合并处理。

在这台机器上使用 Godot 4.7.2、无窗口模式、本地策略和开启军报面板测量：当前战役存档副本推进11日的总耗时从约7.3秒降至约0.26–0.35秒，军报重建22次降至1次，存档11次降至1次。六支驻守测试军队推进30日从约36.2秒降至约1.1–1.2秒，并在30帧中分步完成。耗时包含保存和界面更新，随设备、存档与模型服务变化；真实渲染另用界面捕获检查。

性能测试会对比月度推进和逐日推进的完整兵粮、决策与随机状态，并验证重要军情仍及时停止。运行中的旧游戏进程需要重新运行项目才能加载修复。
